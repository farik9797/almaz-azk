## Текущая версия сайта — что сделано
Старая версия «по брифу» (см. архив в конце файла) была заменена более полной и честной версией, портированной из `almaz` (React-приложения). Все факты из брифа (год основания 1998/25+, реальные телефоны, юр. адрес, БИН, 3 адреса АЗС) сохранены — просто контент вокруг них стал подробнее (продукция с ГОСТами и характеристиками, калькулятор опта, интерактивная карта АЗС, услуги, схема сотрудничества).

- **Дизайн**: светлая корпоративная тема, navy (#0F2A47/#0A1E36/#13315C) + жёлтый акцент (#F5B301) + зелёный (#2E9E5B), шрифт Plus Jakarta Sans. Анимация минимальна — только hover-состояния и клик-переключения (фото-вкладки, аккордеон FAQ, карта АЗС), без scroll-reveal анимаций.
- **Секции (в этом порядке)**: Header (топбар + меню) → Hero → Преимущества → О компании (текст + интерактивная фото-галерея на 4 вкладки + полоса статистики) → Продукция (АИ-92/АИ-95/ДТ с ГОСТами, характеристиками, лабораторный баннер, калькулятор опта с живым пересчётом) → Услуги (6 карточек + баннер автопарка) → Схема сотрудничества (5 шагов) → Сеть АЗС (фильтр по региону, кликабельная карта-схема, 3 карточки станций) → Акции (общие формулировки, без конкретных цифр) → FAQ (аккордеон) → Контакты (3 телефонные карточки + карточка офиса) → Footer → модалка Политики/Оферты.
- **Все CTA — прямые `tel:` ссылки**, форм на сайте нет вообще (см. «Честность контента» ниже).
- **Фото**: реальные технические фото (нефтебаза, АЗС, автопарк, лаборатория) — `assets/images/`. **Важно**: при копировании из клона `almaz` файлы оказались повреждены (побайтовая порча кодировки — UTF-8 replacement bytes вместо реальных JPEG-байт, воспроизвелась даже в git-блобах клона). Исправлено скачиванием валидных версий тех же файлов напрямую с уже задеплоенного `farik9797.github.io/almaz` (там сборка Vite содержит корректные байты). Если в будущем снова копировать бинарные файлы через инструменты чтения текста — проверять `file *.jpg` на результат `JPEG image data`, а не `data`.
- **Логотип**: по-прежнему нет реального логотипа в векторе — используется текстовый знак «АЗК АЛМАЗ» + иконка топливной колонки (Lucide).

## Честность контента (важно помнить)
В `almaz` (React-приложении) при аудите обнаружился и был исправлен системный паттерн фабрикации:
- Неверный БИН `981040002158` → исправлен на реальный `011240001881` (везде — данные компании, текст политики конфиденциальности, копирайт в футере).
- Несуществующий email `info@azk-almaz.kz` → убран полностью (реального подтверждённого email нет — на сайте только телефоны).
- 5 форм с фейковой отправкой (callback/quote/certificate модалки, форма в контактах, подписка в футере) — не отправляли данные никуда (`setTimeout` + фейковый успех). По решению пользователя: **убраны полностью**, все кнопки — прямые `tel:` ссылки.
- Выдуманные конкретные проценты и условия акций (кэшбэк «до 5%», «скидка от 30 литров», «полный возврат НДС») — заказчик этого не подтверждал. По решению пользователя: заменены на общие формулировки без цифр («уточняйте условия на АЗС» и т.п.).
Эти же принципы соблюдены при портировании в статику и в тему WordPress — не восстанавливать старые формы/цифры без явного запроса и подтверждения от заказчика.

## Тема WordPress + ACF (`wordpress-theme/`)
- `azk-almaz/` — тема, механический перенос статики 1:1 (без редизайна) по стандартному пайплайну проекта (`~/.claude/playbooks/wordpress-acf.md`): сначала статика → согласование → потом тема.
- ACF Pro поля: Options Page (телефоны/адрес/БИН/часы работы — общие для шапки/футера/контактов), Repeater на каждую карточную секцию (преимущества, продукция со спецификациями и ценой/плотностью для калькулятора, услуги, шаги, станции АЗС, акции, FAQ, телефонные карточки), WYSIWYG для текста политики/оферты.
- Везде есть дефолты в `inc/defaults.php`, совпадающие 1:1 со статикой — тема выглядит корректно даже без ACF Pro / до заполнения полей.
- **Проверено запуском настоящего WordPress** локально (WP core + официальный плагин SQLite Database Integration, без Docker/MySQL): активация темы, рендер главной, редактирование в wp-admin (в т.ч. вложенные репитеры) — без PHP-ошибок. Локальное окружение (`wordpress-theme/wp-local/`) и собранный `azk-almaz.zip` — в `.gitignore`, не в репозитории.
- Инструкция по установке для клиента — `wordpress-theme/INSTALL.md`.
- **Тема пока не установлена на реальный хостинг** — ждёт, когда у клиента будет лицензия ACF Pro и решение — переезжать на WordPress или оставаться на статике/GitHub Pages.

## Ключевые решения (и почему)
- Источником истины для контента выбран `almaz` (React-приложение), а не старая версия «по брифу» — прямое решение пользователя после того, как оба сайта существовали параллельно.
- Перед переносом в статику/WordPress сначала провели полный аудит на честность контента (не выборочно, а построчно по каждому компоненту) — это и вскрыло системную проблему (неверный БИН в 3 местах, фейковый email, 5 фейковых форм, выдуманные цифры акций). Аудит имеет смысл повторить, если в `almaz` снова появится новый контент от AI Studio до переноса сюда.
- Формы решили не оставлять вообще, а не чинить (например, подключив реальный backend) — решение пользователя: «Никак — оставить только tel:/mailto: ссылки». Это радикально проще и не создаёт ложных ожиданий у посетителей сайта.
- Пайплайн WordPress строго соблюдён: сначала статика и явное согласование, потом уже тема — не наоборот (см. `~/.claude/playbooks/wordpress-acf.md`), чтобы не переделывать PHP+ACF при дизайн-правках.
- Тема WordPress проверялась реальным запуском (WP-CLI + SQLite-дропин), а не «на глаз» по коду — потому что PHP-ошибки в ACF-репитерах (особенно вложенных) не всегда видны при простом чтении кода.
- Год основания 1998/25+ (по брифу, изначально расходился с statsnet.co — 2001) — заказчик подтвердил версию 1998, вопрос закрыт, расхождение больше не поднимаем без явного запроса.
- Логотип не рисовали «от себя» — заказчик говорил, что логотип есть, но не в векторе, файл не прислан; ждём оригинал, а не имитируем его по описанию.
